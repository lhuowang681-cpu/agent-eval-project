# 非 LLM 与 LLM 的公平比较

## 定义与输入权限

| 方法 | 输入 / 行为 | 本轮身份 |
| --- | --- | --- |
| A | 原 trajectory → 原 adapter.analyze；14 类显式异常，不扩分类能力 | 原平台规则，逐字快照 |
| B | 同一 trajectory；闭集参数约束、JSON 答案与结果、实体和顺序、过期值 | 新通用非 LLM 语义规则 |
| B_reviewed | B 的原始候选 → 新审核 | 区分候选生成与接受变化 |
| C | 同一 trajectory → 真实模型原始候选 | **本轮新 48 例未运行真实模型** |
| D | 同一次 C 输出 → 新审核 | **本轮新 48 例未运行真实模型** |
| C_SCRIPTED / D_SCRIPTED | 固定人工候选经 Mock JSON 边界及新审核 | 管道/审核实验，占位，绝非 C/D 模型效果 |

A、B 和未来真实 C 均可看到同一原始节点、evaluation/task、scope、coverage；都没有 Gold 权限。B 只读取节点 JSON、调用身份和顺序，没有 Case ID 分支、答案表、自然语言关键词黑名单，也没有读取作者 title/variant/gold。人工候选由作者预置，不能给它假装“等价模型能力”；只用于在相同输入下检验审核。

B 与审核共享 facts.py 的保守结构解析，B 不调用审核器。这不是完全独立实现，B 与审核一致不能当独立正确性证明；正确性另由人工声明的场景 Gold 核对。真实自然语言映射与单位转换均不是 B 已实现能力。

## 新 48 例离线结果

B 生成 22 个正确候选，覆盖 19/28 个语义正例；审核后仍为 22 个，False Gap=0。原规则只输出 4 条显式异常观察（3 确认、1 分类粒度不可判），语义覆盖 0/28。人工候选经审核保留 17 个，覆盖 14/28；它没有产生任何 B 缺失而又被新审核支持的观察。

这里不能说“规则击败了真实 LLM”：新的 C/D 没有真实模型结果。只能说在当前可验证结构关系内，B 已有很强覆盖；固定人工候选不构成增量发现证据。

## 对旧六次真实 DeepSeek 的同输入复核

仅离线读取上一轮已保存的真实输出，没有重新请求供应商。`results/legacy-comparison.json` 保存每条输入对应的 B、新审核、旧模型输出和 usage。

| 项目 | 数量 |
| --- | ---: |
| 历史真实模型原始候选 | 6 |
| 新审核可支持的旧模型观察 | 4 |
| B 生成并支持的观察 | 4 |
| 旧模型支持观察中 B 无法产生的新增部分 | **0** |
| 原六条比较能用简单 JSON 不等关系计算的数量 | 6 |

旧的两个 A 没有明确闭集，原轮把字段差异算作任务错误，现在不自动支持。这两条字段差异仍可确定性计算，但“业务违规”没有证明。其余四条 B/C 关系增强规则均可发现。因此 **旧 4/4 覆盖不能证明 LLM 优于合理规则，当前已验证的 LLM-only 支持观察为 0**。这是既有简单数据上的事后能力复核，不是独立泛化结论。

## RQ2 结论与下一步

自然语言、同义字段、多轮语义变更和单位换算是合理的增量候选领域；本轮八个相应人工正确候选被审核拒绝，故尚未形成可自动接受的增量能力。需要在新预算和真实 C 输出上测试发现能力，同时为提取/映射设计可追溯验证或人工复核，而不是换个 LLM 充当不可验证裁判。

本轮新增供应商调用 0，新增 Token/供应商延迟/费用均未测量。历史六次 usage 仍可查看，不能把旧延迟当新方案成本；也不能把本机 Mock 耗时称为 LLM 推理性能。

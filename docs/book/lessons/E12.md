# 怎样选一个真正有用的代表案例

## 先决定“代表”是什么意思

报告不可能让审核者逐条读完几百条轨迹，所以要选代表 Case。至少有两种目标：在文本上最像其他记录，或在高频错误形态中最适合排查。目标不同，算法和取舍就不同。

参考包有两条选样路径。cause_convergence 中使用 TF-IDF 与余弦距离选择 medoid；representative_case_selector 则按频率、错误签名、完整度逐层筛选。它们不是同一算法的两个名字。

## 文本中心样本怎样得到

TF-IDF 把错误摘要表示成词项权重向量。某个词在一段文本中出现、又不属于所有样本都常见的词，会影响该文本表示。余弦比较这些向量的方向相似程度，参考实现据此形成距离矩阵。

medoid 从真实样本中选平均距离最小的一条。假设 A 到 B 的距离为 0.2、A 到 C 为 0.8、B 到 C 为 0.7；包括自身零距离后，平均值分别约为 0.333、0.300、0.500，因此选 B。这里的数值用于解释选择过程，没有运行参考算法。

选择真实样本方便审核者回到原轨迹。代价是“文本中心”可能只有通用 timeout 描述，缺少实际输入；它代表常见措辞，却未必最适合解释故障。

## 分层筛选怎样不同

另一条路径先找去重 Trace 数最多的类别，再找该类别中的主流错误签名，然后在这个范围比较信息完整和可调试性，包括用户、Assistant、Tool、错误正文、父链与时间覆盖等。再通过环境频率、失败次数形态和稳定并列规则选择。

假设类别 X 有 20 条、类别 Y 有 2 条，即使 Y 中有一条很长、证据很全，分层规则仍先选 X。这是对“主流问题代表”的偏好；不能说最长或最完整的记录永远获胜。

两条路径还可能使用不同频率单位。教材中讲去重任务治理，不代表所有原报表选样已经统一按任务；实际规则必须说明当前统计的是 Trace 还是任务。

## 代表性与证据强度怎样同时保留

可以先做证据准入，再在合格范围内选择文本代表；也可以分别展示“典型样例”和“证据最完整样例”。前者简洁，后者更容易暴露分组里的差异。选择哪一种，取决于报告读者需要看模式还是做修复定位。

不应为了选一个好看的 Case，隐藏其他样本里不一致的输入来源和后果。报告需要保留选样依据、候选数量及样本限制。

## 大簇会遇到什么成本

成对比较 N 条文本需要处理约 N² 个相似关系。规模增长时，可以考虑先选候选、采样或分层，但这些是需要验证的扩展方案。首轮个人小数据集不必先实现复杂加速，应该先确认样例选择是否帮助审核者理解问题。

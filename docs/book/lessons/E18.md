# 怎样把理解、复现和新增贡献讲成一个项目

## 项目介绍有两层

第一层解释系统：谁需要它、输入是什么、怎样处理、输出帮助什么决定。第二层解释你：参考了什么、理解与验证了什么、新增什么、结果有什么证据。只讲个人贡献而没有系统全貌，面试官难以理解价值；只讲平台功能，又无法证明你的工作。

开篇总介绍解决第一层，本节帮助把第二层组织起来。当前上游非本人开发、个人离线应用尚未实现的事实需要保留；以后真实增量完成，再更新表达。

## 一段介绍的因果顺序

先讲问题：“多轮 Agent 的最后错误不能直接说明内部根因，重试也可能夸大影响。”再讲方案：“关联轨迹、提取失败、区分直接原因与内部候选、审核证据、任务去重并报告。”然后讲具体增量和验证，最后讲限制与下一步。

这种顺序比堆 Python、Redis、LLM 等名词更清楚，因为每项技术都有目标。Redis 属于被测平台的运行协调，并不是自己的离线工具必须使用的组件；面试时应把两层技术职责分开。

## 用一张证据卡准备一次追问

假设后续真的完成证据校验，可以记录：问题是模型结果可能引用不存在节点；新合同要求引用属于本次规范 Trace；改动是加入独立准入检查；反例是 n99；实测输出是待复核及原因；限制是节点存在仍需语义支持。

这张卡就能回答为什么做、怎样做、有没有替代方案、怎么测以及还有什么不足。若只有“加了校验，提升可靠性”，则很难继续深挖。

## 学习、复现与原创分别怎样说

学习是能解释实际机制；复现是按固定条件运行并留下结果；新增是相对明确基线实现了改变。三者都可以体现能力，不能互相替代。复制旧文件不自动形成改进，看过历史报告也不自动形成复现。

代码主要由 Codex 辅助完成时，可以说明自己如何定义问题、核对 Spec 与样例、检查设计取舍及解释验证结果。不要据此宣称亲自逐行写完，也不需要否认自己确实参与的判断与验证。

## 模拟面试怎样训练

项目综述检查全貌；工程深挖检查数据合同、状态、失败恢复和取舍；结果核查检查数字、基线、个人贡献与限制。一次只问一个问题，根据实际回答继续追问，避免背一串标准答案却无法解释具体例子。

学新内容时先讲清机制；复习时先尝试回忆再给反馈；模拟面试时把答案和评分留到结束。三种模式目的不同，不能把初学教材也变成压力提问。

## 怎样记录掌握而不制造分数

读完可以标“已阅读”，答过之后才能记录本次表现，完成实际实验再登记验证。没有回答就保持未评估；一次不会也只是这次问题暴露的缺口。记录题目、原回答、具体纠正和下一步复习，比只存一个高分更能帮助后续学习。

最终目标是能拿一个真实或明确标注的合成案例，从请求讲到报告，解释设计、替代方案、故障和结果；再准确指出哪些属于参考，哪些是自己完成且可查证的增量。

# 本项目的模拟面试方式

## 什么时候使用

先学正文、再做复习。只有用户要求模拟面试时进入本模式；当前默认工程深挖，用户也可选择快速全貌或源码核对。沿用来源 interview-prep 的分方向、原回答追问与事后报告思想。

## 三个方向

1. 项目综述：业务问题、服务对象、输入输出、技术职责与端到端过程。可以从 90 秒介绍或一个具体失败案例进入。
2. 工程深挖：任务 / Trace 身份、调用关联、结果回填、取消与预算、证据门禁、排序、报告或评测。按 topics.json 选择与上一场不同角度，且至少覆盖一个失败反例。
3. 个人贡献与验证：来源基线、实际新增、替代方案、真实输入配置与结果、尚未完成部分。无数据不编指标，源报告不认领为个人成绩。

每次一题，根据用户原回答自然追问；同话题最多三次追问。追问顺序可以是为什么、替代方案、故障与验证，不机械念完预置题。用户说跳过或结束即停止对应段落。

## 怎样选题

先查真实历史，选择未问过的角度；同一场跨不同知识域。开始前由工具实际生成或记录一个选题种子，可用于同分候选的可复现选择，不声称模型猜数字就是真随机。用户指定题目时以用户为准。首轮优先已学内容，未学内容不作为突然的掌握要求。

## 记录和反馈

每次收到回答，先在 docs/learning/LEARNING_PROGRESS.json 的会话记录中保存问题与回答原文，再继续下一题。题目原文、回答原文、教练解释和参考回答分开保存。离线书只存用户自己的笔记，不自动获得聊天回答。

结束后再给反馈：实际问答、正确处、具体错误、参考回答、事实准确 / 流程理解 / 设计取舍 / 证据验证四维评价、下一步。可保存到 docs/learning/interviews/ 下的日期文件，但只在真实面试会话后生成，禁止预填虚构原问答或评分。

评分只说明本次表现。没有实际回答的点保持未评估。原先学过但忘记的点注明具体问题与时间，不永久固化为用户能力判断。

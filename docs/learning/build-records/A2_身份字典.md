## 对象与用途

| 对象 | 用途 | 不能直接替代什么 |
| --- | --- | --- |
| Task | 表示可验收的业务目标，统计受影响的不同任务 | 不直接等于一条Trace或一次调用 |
| Trace | 标记一段观测记录，限定节点和调用的来源范围 | 不直接代表独立业务任务 |
| Node | 定位具体消息、动作或结果，供证据回查 | 不等于一次完整工具调用 |
| Call | 关联某次工具请求与对应返回 | 新重试和旧调用是不同身份 |
| Session | 表示会话关系，一个会话可有多个任务 | 不等于任务数或用户数 |

## 教学字段约定与来源边界

- task_id：优先使用有明确业务定义的来源任务身份。来源缺失时，分析分组回退键应单列并说明口径，不冒充已确认的任务身份。
- trace_id：保留来源Trace身份，一个业务任务跨多条Trace需要显式关联依据。
- node_id：在来源与Trace范围内定位具体记录；不无条件假设跨来源全局唯一。
- tool_call_id：在对应来源和Trace等作用范围内关联请求与结果。一次调用可产生请求、返回等多个节点，不能仅按调用ID把所有节点合成一条失败。
- session_id：保留来源会话身份，缺失用null/未知；不得以Trace ID回填后声称得到真实会话数。
- 旧来源的effective_trace_id、topic_id、sessionId及回退规则因入口而异，字段名本身不足以证明它们对应上述业务对象。本文是新增合同建议，不声称参考脚本已统一实现。

## 去重规则与失败反例

重复采集同一结果：核对来源范围、Trace、稳定结果节点身份及内容。同一记录的重复副本不重复计数，来源信息保留。相同身份却内容冲突时保留冲突待复核，不直接丢弃。

真实重试：新的调用与结果即使工具名、参数、错误文字相同，仍是另一次事件。错误文字可用于同类问题分组，不能单独作为事件唯一键。

影响统计：保留真实事件数量，再根据可靠任务身份统计不同任务；不能先把同任务所有调用合成一条原始事件。

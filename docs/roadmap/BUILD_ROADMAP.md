# 从现有代码反推项目搭建顺序

日期：2026-10-23。参考用户粘贴的“阶段→子任务→状态→日期→目标/输入输出/文件/验收”结构，为当前 Agent 评测参考包重新设计。没有照抄 RAG 的技术模块、68项数量、2026年1月日期或测试成绩。

## 这样走一遍，为什么有助于理解

单看最终架构图容易记住模块名，却不知道为什么需要它。按搭建顺序学习，可以先看到一个更简单的方案，再看具体失败如何迫使系统增加机制。例如：单次工具调用能工作，但结果未回填会失败，所以引入状态与事件；错误记录很多，所以需要统一身份和去重；候选标签合法却可能引用假节点，所以需要独立证据门禁。每一步都回答“现在多解决了什么、付出了什么代价”。

这是一条合理的教学重建，不声称上游作者真的按这个顺序开发。对参考部分先用工程解释和固定例子走通；对个人增量再实际写代码与验收。能够解释、手算和判断反例同样是产物，不要求用户手写所有模块或部署整个企业平台。

## 全局搭建地图

A 业务与合同 → B 最小运行循环 → C 状态/异步/观测 → D 数据接入 → E 失败事实与责任 → F 去噪/分类/证据 → G 准入/排序/案例 → H 报告/指标 → I 个人离线实现 → J 评测与交付。

A—H 不代表要再开发一个通用 Agent 平台，它们帮助理解被测对象和参考分析器。I—J 聚焦自己的合成 JSONL→确定性分析→严格门禁→任务去重→审计报告，形成真实个人增量。

## 状态分三种事实

- 参考基础：源码可见、部分具备、仅文档/教学、明确缺口或待新增，是对已有材料的判断，不是运行成绩。
- 走通状态：你是否在教练讲解后完成输入到输出、反例与复述。初始全部未开始。
- 新增实现状态：只用于 I—J，代码/验收是否实际完成；与学习进度分别更新。J3 模型对照为可选，不阻塞首轮收口。

当前 39 项必做走通、7 项必做个人实现，以及 1 项可选扩展。不是40次独立课程：同一节 E 教材可覆盖多个搭建任务，按现有每天约5小时、15天首轮和18—20天巩固窗口合并推进。若基本运行流没有掌握，先缩小新增范围，不压缩理解。

## 与现有教材怎样配合

先读项目总介绍，再从 A1 开始。每次先讲对应 E 节中的完整场景，再按本任务的输入输出走一遍，留下小产物，最后选择复述或复习。没有讲过的内容不先考。源码路径是给查证用，主线仍是工程机制、取舍、失败和验证。

前置关系是工程解释与组装依赖，不是要求用户先通过全部教学才能允许 Codex 编码。用户以后授权开发时，代码可按真实工程前置自主推进；学习进度独立维护。本次只交付规划与进度管理，没有启动业务实现。

## 第一站 A1 的示范怎么走

输入是一个业务需求：“查询指定日期订单”。先说明 Agent 平台会决策、执行工具并留下轨迹；分析器读取这些事实、关联调用与结果、识别失败、分析证据并汇总报告。接着改变工具结果为外部500，解释为什么失败不直接等于平台参数代码错。最后形成一张范围图，指出当前参考和自己的拟增量。这里给出教学示范，不据此把用户走通状态打勾。

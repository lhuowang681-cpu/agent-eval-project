路径基准为agent-eval-project；P/B指当前默认平台，L指旧参考路线，R指第三轮研究脚本。每个锚点核对原文件和行号并记录SHA，不把旧runtime-reviewed当最新平台。key_sources保留相同相对目录，源码只作定位，课堂每次选2—3处。

## A级深入路线

<a id="t1"></a>

### T1 Agent指令与状态驱动执行

- 时机：V1后，约60—90分钟；按薄弱处选，不预先全讲。
- 核心原理：把下一步决策表达成指令，将模型/工具等副作用交Executor；phase与state决定后继，不是把所有行为叫一次LLM调用。
- 项目作用/实现：GeneralChatAgent产指令，Runtime.step推进状态；服务端Runtime/Executor接执行与保存。
- 替代方案与代价：单循环原型更少抽象；状态/指令分工更容易测试与替换执行器，代价是合同和阻塞态处理。
- 核对源码：[P05](03_核心技术与源码证据.md#p05)；[P06](03_核心技术与源码证据.md#p06)；[P07](03_核心技术与源码证据.md#p07)；[P08](03_核心技术与源码证据.md#p08)。
- 边界与局限：默认预算helper为128000×0.65=83200且严格大于才触发；主要构造链只传enabled，不能声称自动读取当前模型窗口。步数、forceFinish、等待人工和取消分别讨论。
- 面试解释方式：先讲一次工具往返，再讲谁决策/谁执行/谁保存，最后用超预算和取消解释边界。
- 进一步追问：工具已经发出后取消能否撤销副作用？哪些信息被压缩会影响后续工具调用？

<a id="t2"></a>

### T2 批量运行、K指标与终态幂等

- 时机：V3后，约60—90分钟；按薄弱处选，不预先全讲。
- 核心原理：将请求受理、执行完成、评分完成和Run聚合分层；通过数据库条件写阻止终态被迟到覆盖。
- 项目作用/实现：本地完成hook、线程完成聚合、updateIfUnfinished/finalizeIfActive构成关键保护链。
- 替代方案与代价：只在内存设finished标志难跨重入；条件更新可依赖DB原子性；全面改队列并不自动解决业务幂等。
- 核对源码：[P09](03_核心技术与源码证据.md#p09)；[P10](03_核心技术与源码证据.md#p10)；[P11](03_核心技术与源码证据.md#p11)；[P16](03_核心技术与源码证据.md#p16)；[P17](03_核心技术与源码证据.md#p17)。
- 边界与局限：K任一通过计该题passed，全部通过另记；score为max，不是均值。资源primary按线程平均并另存total。当前maxConcurrency仅声明未在编排消费，不能做调参效果承诺。
- 面试解释方式：用超时→迟到成功、重复回调、K最后线程完成三个时序讲设计和真实修复。
- 进一步追问：重复finalize如何保护duration/metrics？completed中含failed题该怎样对用户解释？

<a id="t3"></a>

### T3 LLM Judge输入与评分器可靠性

- 时机：V4后，约60—90分钟；按薄弱处选，不预先全讲。
- 核心原理：评分本身也是不可靠外部调用：先定义任务、参考、输出、标准，再限定分数结构和错误语义。
- 项目作用/实现：evaluate选择matcher并计算Σ(wᵢsᵢ)/Σwᵢ；阈值默认0.6。generateJudgeObject把初始化计入硬截止，接原ModelRuntime。
- 替代方案与代价：规则更确定但语义有限；结构化LLM更灵活但要校准；另造客户端会复制配置/取消逻辑。
- 核对源码：[P12](03_核心技术与源码证据.md#p12)；[P13](03_核心技术与源码证据.md#p13)；[P14](03_核心技术与源码证据.md#p14)；[P15](03_核心技术与源码证据.md#p15)。
- 边界与局限：合法0分≠error；NaN/越界/空reason不接受。Case配置整份覆盖，非字段深合并。硬截止不保证供应商停止计费，Run资源指标不能自动认为含Judge开销。
- 面试解释方式：以“答错”“空JSON”“忽略signal”三种情况说明评分与评测生命周期的分工。
- 进一步追问：模型JSON合法但判断偏差如何测？为什么不把所有异常记0分后算通过率？

### T4 证据身份、跨语言合同与独立任务

- 时机：V5—V6后，约60—90分钟；按薄弱处选，不预先全讲。
- 核心原理：同一证据跨存储/语言仍要保持所属和原字段语义；诊断使用独立任务状态，不能污染评分。
- 项目作用/实现：SQL提取→scope/nodes/digest→async_tasks输入快照→版本化Python→validateDiagnostic→独立result。
- 替代方案与代价：拼文本最简单但不可审计；固定本地进程少部署；常驻HTTP服务/分布式队列需更强需求才引入。
- 核对源码：[B01](03_核心技术与源码证据.md#b01)；[B02](03_核心技术与源码证据.md#b02)；[B03](03_核心技术与源码证据.md#b03)；[B04](03_核心技术与源码证据.md#b04)；[B05](03_核心技术与源码证据.md#b05)；[B06](03_核心技术与源码证据.md#b06)；[B07](03_核心技术与源码证据.md#b07)。
- 边界与局限：派生call非原生span；缺provider/operation事件保留coverage。重复ID去重仍需lease fence；序列化/Unicode/数值表示必须一致，错误引用不能靠补造字段通过。
- 面试解释方式：拿一次真实持久化工具error讲来源，再讲两个worker和迟到结果；“job执行成功”不提升为“根因正确”。
- 进一步追问：输入摘要能替代userId校验吗？engine变更后怎样保留旧诊断？

<a id="t5"></a>

### T5 因果边界、选择性预测与实验验收

- 时机：V7—V9后，约60—90分钟；按薄弱处选，不预先全讲。
- 核心原理：结构合法、引用存在、观察支持、内部根因支持是逐级更强的命题；弃权会改变覆盖，不能只看接受后精度。
- 项目作用/实现：默认审核严格且有误拒；旧validator不统一必经。phase3固定候选五组、冻结原/候选与holdout，独立输出裁决保留类别歧义。
- 替代方案与代价：一味放宽可能错误归因；一味严格可以全弃权。应同数据同候选比较结构/引用/支持门禁，区分根因与观察。
- 核对源码：[B08](03_核心技术与源码证据.md#b08)；[L01](03_核心技术与源码证据.md#l01)；[L04](03_核心技术与源码证据.md#l04)；[L05](03_核心技术与源码证据.md#l05)；[R01](03_核心技术与源码证据.md#r01)；[R02](03_核心技术与源码证据.md#r02)。
- 边界与局限：模型/审核共享弱规则会继承盲点；未知不算正确，无法判真也不能直接记错。全无安全输出时准确率NA。完整审核组safeCandidate=null不抹掉adapter存储的带标记观察。
- 面试解释方式：讲第三轮开发局部改善、独立无提升、后验退步及恢复原版的决策；这比只报测试数更能说明工程判断。
- 进一步追问：怎样避免标签泄漏？generic fallback是否允许当子类上位结论？怎样验证一条真实最早异常链？

## 如何验证一项技术判断

先找入口，再找实际调用，再看返回/写入，再读测试或实验条件。字段声明不等于消费，helper存在不等于主链传入了真实模型窗口，validator存在不等于模型入口必经。源码确认实现，实验确认特定条件下的行为；两者都不能代替真实质量标签。

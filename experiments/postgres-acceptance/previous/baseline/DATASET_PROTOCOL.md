# 数据、标注与冻结协议

## 数据范围

48 条新的单作者合成场景，31 个已知正确观察目标分布在 28 个语义正例；37 个案例有确定的正/负标注，其余 11 个主要为根因/结果/实体无法确认。允许多标签，不标唯一内部根因。

不是把上一轮 2025/2024 JSON 例子简单扩增：包含中文纯文本任务和回答、同义状态、不同字段名称、金额单位、否定句、多轮覆盖、合法同比/基期、多调用旧值/恢复、无关显式异常并存、重复事件、复用身份、跨 Thread/Case、缺失、伪造引用、注入文本和正常负例。仍有共同节点构造器和相似结构，不能等同真实数据多样性。

场景目录与判断依据全部在 data/build_cases.py / cases.jsonl。每条含 task、完整 synthetic trajectory、原始固定候选、Gold 命题/真值/requiredRefs/因果未知和 rationale。`scriptedCandidate` 不是模型结果，Gold 也不是模型/审核器逆向生成；数据代码不导入 candidate 或 evaluator。

## 标注层次

- truth=correct：作者预设事实支持该有限观察；不代表唯一根因。
- incorrect：观察与预设业务语义矛盾，例如允许基期却报参数错误。
- unknown：现有可见事件不能确认，如同 Call 冲突或强行推断内部根因。
- supportable：从完整被引材料，人工是否能支持该命题；并非“当前 JSON 审核器是否已经实现”。
- requiredRefs：必要原始节点和字段；摘录还须真实、Scope 一致。相同重复事件在独立指标中按等价逻辑结果处理，不依赖审核器返回值。

## 数据审查与版本记录

候选开发用独立小型开发 fixture / 14 项回归，并没有使用这 48 条调算法。执行顺序的 UTC 收据保存在 ALGORITHM_FREEZE、data/DATA_FREEZE、data/LABEL_REVIEW、data/LABEL_ADDENDUM 与 PROTOCOL_FREEZE：

1. 候选与 Prompt/Mock 实现通过开发测试，先冻结 candidate/*.py。
2. 生成 48 场景，保存初始数据与生成器 SHA，不覆盖原 JSONL。
3. 正式运行前复核标签：初始八个自然语言/映射/单位场景把“机器未实现”混成“证据不足”。LABEL_REVIEW 改为人工支持、机器未实现，确保其拒绝计入 False Gap。原数据字节保留。
4. LABEL_ADDENDUM 补充两例的有限状态观察：不可验证的 root 候选不能抹掉同时存在的可观察矛盾。原 root 标注仍保留为 unknown。
5. 冻结复核层、数据、evaluator、运行脚本和指标测试，再执行一次正式实验。run_experiment 每次校验 SHA，已有正式结果则拒绝覆盖。

复核发生在观察任何正式候选输出之前，不是看到分数后修改 Gold。初始标注和复核层都交付；正式数据视图为原 JSONL + 两层显式复核，case-results.json 保存应用后的 Gold。

## 指标口径

候选正确率：correct / 所有输出，unknown 不计正确；另报只对可判命题的 judgedAccuracy，不能混用。接受准确率仅统计被接受声明，无输出为 N/A。

有效覆盖：有正确且证据足够的观察的语义正例数 / 28。多标签另报观察目标命中数 / 31。案例级严格正确率：确定标注的 37 例中，正确观察完整检出且无错误/不可判输出的比例；另外 11 例不因弃权而被奖励为正确。

False Support：被接受但不是事实正确且证据充足的声明数，包括错误、未知、假引用和 scope 不符。False Gap：原始候选正确且有足够人工证据、却未保留的命题数。trueObservationRejects 更宽，包含真值正确但候选引用无效的被拒数量；后者不都应视为误拒。

引用有效率仅原文字段存在率；不代表语义正确。Abstention 为零输出案例 / 48，包括合理负例弃权和漏检，不单独当准确率。根因正确率不估计，所有 causalRoot=null。A 的 generic 显式异常若与更具体标签粒度无法对应则记不可判，不能直接算错或算对。

## 独立性限制

用户明确要求不使用子 agent，本轮没有另找标注作者。数据、实现、复核与指标仍由同一作者完成；流程/代码分离和哈希冻结减少事后调参，但不构成严格独立盲测。没有独立人类复核、真实用户数据或新供应商输出。本集应称“冻结的过程分离合成验收集”，不得称“盲测证明泛化”。

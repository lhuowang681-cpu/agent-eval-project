# 第二轮正式实验结果

**RQ1 得到有限正结果：**同一批冻结人工候选，旧审核 False Support=8，新审核=0；原/新 False Gap 均为 8，有效覆盖均为 14/28。在此集合没有观察到修复增加误拒。

**RQ2 尚未得到真实模型增量证明：**增强规则已有 22 条有效观察；新 48 例没有付费调用，C/D 仅人工候选 Mock。旧六次真实输出离线复核，LLM-only 被支持观察为 0。因此继续保持 Shadow。

## 实验条件

48 条新合成场景、28 个语义正例、31 个正确观察目标；37 例为确定正/负，11 例主要不可判。算法在数据生成前冻结，标注复核层与指标在正式评测前冻结；单作者、非严格盲测。见 DATASET_PROTOCOL。

真实新模型调用 **0**。本轮没有沿用密钥发请求，也不把上一轮 6 次预算当可重复使用的新授权。Mock 是显式固定人工响应的 JSON 边界，不模拟模型真实能力。真实 C/D 在新集合上的成绩为 **未验证，不是下表的 C/D_SCRIPTED**。

所有方案看到相同 trajectory；人工候选由数据作者预置，不据此宣称模型输入公平或模型优越。逐案例输入、原始 Mock 文本、解析候选、Gold、接受/拒绝、原因与配置在 results/case-results.json。48×7=336 行方法级结果在 per-case.csv。

## 历史真实模型复核

旧六次真实 deepseek-flash 响应被离线复用，绝非重跑。它有 6 个候选，新审核接受 4 个；B 同样产生并支持这 4 个，新增有效 LLM-only=0。另两条是简单字段差异，缺少闭集约束不能证明业务违规。六条底层字段差异都可用 JSON 比较计算，不能据旧 4/4 声称 LLM 有必要性。该事后复核也不是新独立泛化实验。

## Token、耗时和费用

新增供应商调用 0；新集合模型 Token、模型延迟、实际模型费用均 NA。各条 offlineSeconds 是真实本机规则/Mock/审核合计耗时，不是推理耗时。旧六次 usage、model alias、响应和已披露 7537 Token 保存在 previous 及 legacy-comparison，历史账单仍未核验，没有将旧成本移植成新实验成本。

## 回归、冻结和限制

新 18、旧 Shadow 原版 15、原 Python 36、原桥接 TS 71 项通过；原平台关键 10 文件和上轮 54 文件字节未变。旧 15 项直接换用新版则为 12 通过、2 失败、1 异常，均依赖无闭集也接受 A 的旧假设。原测试未改，这些兼容变化保留在日志；不宣称全部旧测试在新策略下通过。未重跑历史 945 项、PG/UI、全库类型检查。

已保存 SOURCE_SNAPSHOT、ALGORITHM_FREEZE、PROTOCOL_FREEZE、数据冻结与复核层、regression.json、所有日志和失败初版开发测试。正式评测后未改候选、冻结数据或指标来提高分数。

质量结论：审核安全性在当前合成集合改善，八条语义误拒仍存在；简单规则已覆盖当前可自动核验关系，真实 LLM 的额外发现价值与是否值得花费成本仍待验证。**不推广、不改默认链路。**

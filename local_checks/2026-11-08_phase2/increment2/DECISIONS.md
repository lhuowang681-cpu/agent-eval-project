# 增量二技术决策记录

| 决策 | 选择原因 | 放弃方案与代价 |
| --- | --- | --- |
| 复用async_tasks但独立诊断type/status | 已有表可保存不可变输入和结果，避免评分回调并发写同一JSON | 不塞入runTopic.evalResult，不用reportResult改评分；代价是需要单独查询诊断 |
| 固定Python子进程 | 无新网络服务，复用现有纯规则，失败隔离边界清楚 | 不建Python API，不新增队列；代价是需显式单机worker和可执行文件配置 |
| 版本化输入快照 | Run/Case可重试，消息可变化，不能只用caseId复用旧结论 | 同一输入与代码去重，变化则新任务；增加有界重复存储 |
| 原子lease与token | 崩溃后可重领，迟到旧attempt不能改新结果 | 不宣称只执行一次；租约过期可重复计算，但只允许当前token落库 |
| 源字段引用与独立校验 | 引文必须来自本轨迹原节点，不能相信模型给的ID/置信度 | 不靠summary重建error，不按工具名字推来源；缺证据时覆盖率降低但不误定责 |
| 保留未知结果 | 评分失败只说明答案没达标，不证明工程故障或内部责任 | 不强制每个失败分到56模块，避免把unknown伪装Observability故障 |
| 精确跨语言表示 | Python JSON的Unicode排序与小数指数不同于JS，合法引文也可能被误拒 | 以JSON wire类型对齐证据文本并真实跨进程回归，不取消quote校验 |

教学可按真实失败顺序展开：先完成最短stdin/stdout→加身份合同→实现只读DB提取→发现两层错误字段丢失→引入独立任务→复现重复/迟到→使用lease token fencing→验证评分完全不变。

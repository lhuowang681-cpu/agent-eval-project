# 第三轮：归因质量的数据与标签审计

审计日期：2026-11-08。本次只读现有源码、说明、归档目录、报表字段和历史运行结果；没有修改算法或phase2，没有调用真实模型、安装依赖或全量解压ZIP。只新增本文件和DATA_AUDIT.json。

## 结论

已有工程执行证据、合成边界集，以及两份文件名标注“脱敏”的历史报表。但在本次检查材料中，**尚无已核验的独立根因金标测试集，也没有已核验的生产完整轨迹集**。当前可确认的独立root-known金标数为0；实际历史真值数量未知，不能据此断言历史上无人标注过。

因此，现阶段不能给出“根因归因准确率”，UNKNOWN也不能算正确。应先解决来源、证据充分性、标签独立性和测试集隔离，再评估质量。已有确认的工程缺陷和修复前后回归可作为后续因果样本材料；它们尚未整理成独立、冻结并经责任模块复核的56模块金标。

## 历史XLSX：只可用于来源与可用性审计

已按spreadsheets技能做只读ZIP/XML核查，原工作簿、公式和布局未改；没有导出原始行、真实Topic/Trace/Call ID、用户内容或凭据。DATA_AUDIT.json只保存schema、行数、缺失率、不同引用计数、文件hash和去标识摘要。

两份文件分别是原ZIP内的`tripyoyo工具报错2026.08.06_脱敏.xlsx`和`tripyoyo报错日报2026.08.06_脱敏.xlsx`。文件名的“脱敏”是来源方命名，不构成脱敏验收证明，生产来源真实性和标注权限也未独立核验。

- 工具明细156条：工具名、错误类别、原始报错证据、Topic引用、Trace引用、Call引用和原粗分类字段均非空；不同非空引用计数分别为47、64、156。**仅为引用计数，不代表对应完整原始轨迹可用，也不代表独立用户任务数。**
- 日报概览1条：责任模块字段非空，但没有找到独立标注者、复核时间、争议处理和判定依据的正式标签台账。
- TRACE_AUDIT共有10个XML行，首行为表头，另有2个仅样式空行，实际7个非空证据行。关键输入栏6/7空，关键输出栏1/7空，工具名栏1/7空；表格没有独立parent/operation字段。
- 上述是**该表栏位**的缺失率，不是原Langfuse系统字段缺失率；叙述页可能另有摘要，不能把单元格空白直接断言为原始事件缺失。反过来，摘要和非空错误证据也不能替代原始调用/Provider请求、事件父子关系、配置版本与完整错误体。

历史文档还指出：某些导出曾以effective_trace_id/topic_id代理任务，原trace_id为DBNULL；这是特定历史来源的限制，不能外推所有XLSX。本次报表引用均非空，也不证明与那个导出采用相同映射或可回链至原系统。

`developer_issue_labels.py`会按类别/签名生成模块与开发问题，`simulate.py`存在合成数据及随机置信度；`references_reporting_spec.md`要求批量前人工确认样例，但要求不等于已完成确认。上述代码或报告输出都不能作为它们自己的独立真值。

## phase2真实运行保留了什么

最终通过的HTTP结果含4个诊断轨迹，节点数分别2、2、2、5。前三个是合成质量失败用例，无结构化运行错误；最后一个含1个结构化工具错误与1个有限观察。

4/4有operation引用，4/4没有traceId；已保存的parent引用无悬空，但4/4均coverage=false，原因包括operation_events_unavailable、provider_request_payload_unavailable和trace_id_unavailable。前三个诊断unknown，最后一个needs_review/builtin_tool_failure_unclassified，全部moduleId为空。

这些结果证明了工程路径和部分证据保存，不能证明完整因果链或模块准确率。对“工具确实返回错误”的观察，已保存字段可能足够；对“哪个内部模块最先制造错误”的责任结论，必须另检查该结论所需的输入/输出与版本证据。充分性应按声明层级判断，不能靠单一complete标记自证。

## 旧12例实验不能怎样解读

1. **根因分母不存在。**12例causalOwnerKnown全部false；模块弃权12/12只能表示没有作责任结论，不能写为根因正确12/12。
2. **样本非独立盲测。**大部分用同一外部HTTP 500轨迹作字段、引用、来源、覆盖或摘要变体。没有训练/开发/测试冻结清单、按故障家族隔离或独立复核记录。
3. **不是模型质量对比。**direct端原样回显syntheticCandidate，恶意结论是预设的；真实SDK/HTTP执行不赋予它真实LLM推理含义。
4. **存在规则自洽循环。**合法候选摘要从原规则产生；reviewer又调用同一adapter.analyze，并限制为它的摘要模板。审核supported只能证明符合该政策，不能作为独立语义正确标签。
5. **手工标签未独立核验。**directSemanticallySupported由开发者按case种类设定；rules/reviewed指标分支默认语义支持，再检查类别/模块，并非独立证据复核。只能作开发期边界期望。
6. **字段名混合层级。**旧observationClaims实际把非空category、非空module或root_cause都计为claim；direct的11个claim包含责任结论，不能叫11个纯观察。
7. **分母需明确。**direct的8/12是全例不支持结论负担，不是已输出结论的选择性风险8/11。3/12“非法或无证据”合并了1个非法类别/模块和2个不存在引用。
8. **审核拒绝不等于结论虚假。**10/12未被审核支持包含完整性限制和合理改写的保守拒绝；开发标签认为不支持的是8/12，两者不可混称错误率。
9. **9/9不是根因覆盖。**9是手工选定的有限观察候选分母；其中11/12合成轨迹被手工设为complete=true，与真实执行提取4/4 complete=false不同。
10. **没有相对规则的质量提升证据。**原规则已不作任何责任模块结论；审核后观察覆盖只有1/9，存在missing_parent政策限制和supported_paraphrase模板错拒。不能只报拦截不安全候选，却隐藏覆盖损失。

## 后续严格指标

先冻结评测单位：明确是去重调用、case线程轨迹、一次run还是用户任务；同一原事件、同模板/故障家族、重试和不同报表副本不能跨开发/测试集合重复计数。事件失败数、失败轨迹数、受影响任务数分别报告。

| 指标 | 严格分子/分母 | UNKNOWN与缺失数据 |
| --- | --- | --- |
| 根因严格正确率 | 有因果证据且模块+机制落入独立认可标签的预测 / 全部root-known测试例 | 弃权不计正确；分母含弃权。当前分母未建立，值为不可用 |
| 根因选择性风险 | 错误或无因果支持的责任结论 / 已输出责任结论 | 不可核验单列，不给正确信用；无输出时风险不可用，不能写0风险 |
| 根因覆盖与弃权 | 输出责任结论例数 / 全部预定测试例，同时给root-known占比与弃权率 | 高弃权不是高根因正确率 |
| 支持观察召回 | 有非空、类别正确且证据独立支持的观察例 / 全部可观察失败正例 | UNKNOWN为漏检，不能计正确 |
| 观察选择性精确率 | 独立支持的观察声明 / 全部已输出观察声明 | 排除root-cause声明；没有输出时不可用 |
| 无失败信号误报率 | 无失败正确信号却输出失败观察的例 / 无失败对照例 | 安全弃权可作安全行为统计，不转成根因正确 |
| 引用存在有效率 | 同run/case/thread/digest内节点和原字段引文有效的引用 / 全部引用 | 无引用时不可用；另报缺必需引用的声明。字符串命中不能证明语义或因果 |
| 证据支持率 | 独立确认能推出所声明观察/责任结论的声明 / 已评审声明 | 不用规则一致或模板白名单接受率代替 |
| 来源充分覆盖 | 独立确认足以支持指定层级声明的例 / 全部预定例 | 分字段报告输入/schema、错误体、父序关系、来源/Call ID、配置/版本等；未知单列 |
| 风险—覆盖曲线 | 在开发集冻结阈值后，于独立测试集计算风险与输出覆盖 | 保留弃权与不可核验分层，root与观察分开画 |

root-unknown的样例不能擅自补成某个模块，也不能因为系统输出UNKNOWN而增加正确数。正常对照、纯观察、根因明确和根因不可识别应分层，不把所有UNKNOWN混为一种任务。

**真实模型token和费用当前不可用，JSON使用null及原因，不写0。**Mock usage是伪计数，不能估真实模型费用、推理效率或缓存收益。已有HTTP/命令wall time可保留为本机工程耗时，并标明Mock条件，不能称真实模型响应延迟。

## 数据入集门槛

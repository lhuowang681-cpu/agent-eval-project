# 第三轮：先诊断，再做有限优化

冻结起点为第二阶段最终工作副本，不改第二阶段结果和96份source-reference。研究代码/数据/结果均写入本目录。

## 顺序与门禁

1. 冻结原版Python审核与相关入口；只读审计每条规则、旧12例direct及规则候选、真实HTTP轨迹，记录拒绝与非适用。另审计数据来源、完整度、标签可信度与独立集。
2. 固定指标、开发集和独立作者holdout。holdout作者不调用审核器，不看优化代码；主实现者在方案/代码冻结前不读取其具体案例。该隔离只能降低调参泄漏，不等于多标注者盲审或自然独立数据。
3. 相同轨迹/固定候选对照：原规则、直接候选、结构审核、引用有效性审核、完整审核。离线候选只是测试夹具回放；旧SDK Mock收据只证明传输，不证明LLM效果。没有可确认真实模型配置则真实模型分支标blocked。
4. 根据诊断只选择1—2项有证据的局部修改，不降低阈值，不增加部署组件；原版和优化版均跑相同holdout，保留逐例输出。没有改善照实报告。
5. 回归固定Python/TS桥接和任务链路，核查原输入、评分与身份不变；形成报告、源码索引、补丁及可回滚包。

## 预先固定的统计原则

- 根因归属与故障观察分别统计。已知合成注入根因的分类准确率以全部已知根因例为分母，弃权不算正确；另报已作出且有可信标签的根因结论准确率和覆盖率。
- UNKNOWN/ABSTAIN/null不是正确类别，也不是错误归因；它们是未回答。执行error单独列出，不吞并进正常弃权。
- 错误归因率分已证错误/不支持结论/不可判定，不能用“审核拒绝”自动给模型贴错误标签。
- 引用有效率只检查作用域/节点/字段/精确引文存在，与支持结论单列；无引用时报告0引用数及null比例。
- 被接受结论准确率以实际输出结论为分母；部分指标需要独立标签，标签缺失则null，不由审核器自己给自己打真值。
- 有效观察覆盖=正确且有支持观察/观察可回答案例；原始作答覆盖、根因覆盖、弃权率分别列出。
- 风险—覆盖率比较使用预先定义的审核强度离散操作点，不伪造置信度阈值曲线；同时保留每例错误集合和分母。
- Token、LLM延迟和付费成本未调用真实供应商时为null；只测本机审核/规则执行耗时，不混成模型性能。

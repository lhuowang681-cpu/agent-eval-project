# 面试与工程学习技术总结

可以这样介绍本次工作：

“项目原有 Agent 运行、评分和 Trace 持久化，也有 Python 规则归因。规则能抓工具显式异常，但工具执行成功不代表 Agent 做对了，例如年份参数与任务不符、回答和查询结果矛盾。我做了一个独立 Shadow 原型：LLM 跨步骤找候选，输出原节点、字段、摘录和比较值，再用确定性局部审核验证引用、实体和新旧结果关系。它只承认可观察偏差，不据此断言内部责任模块。原规则、评分、诊断 API 和数据库默认行为都没改。”

## 应掌握的工程难点

**第一，先找到实际运行链，再谈复用。** 历史分类脚本不等于平台功能。默认平台使用 adapter/rules_pure 和 TS 独立任务；历史 ModelRuntime Mock 实验又是另一条链。读清入口、调用者、身份和持久化边界，避免重复实现或误把参考脚本上线。

**第二，区分四件事。** 引文真的存在、命题事实正确、引用足以支持命题、命题是真正根因，各有不同证据要求。真实引用也可以支持错误理解；字段矛盾也不自动证明某个内部模块负责。

**第三，合同决定能安全证明什么。** 三类新观察独立版本，不塞进旧异常分类。原 scope 和 inputDigest 绑定输入；多故障逐项审核。模型自由摘要不被整体背书，只输出审核器实际验证的规范化字段命题。对无法核验的自然语言保持 Needs Review，是当前能力边界。

**第四，局部充分与全局完整不同。** 缺 provider span 不一定妨碍验证已引用的年份参数。但缺新结果或实体信息会破坏具体命题。短摘录可以借同一被引字段的 JSON 封装，不能跨到未引 error 字段补证据。这是对第三轮误拒经验的有限合同修正。

**第五，实验比平均分更重要。** 人工候选回放验证拦截机制；真实模型测试发现能力；独立未见集验证泛化。三者不能混用。固定候选不得叫 LLM 结果，弃权不得叫正确，根因不可判不得算普通错误或正确。发现指标脚本误算时，应保留原结果、冻结数据、修指标并披露过程。

## 可以引用的真实结果

- 6 次真实 DeepSeek 调用，输入仍是合成 Trace；4 个语义正例检出 6 条正确且支持的观察，2 个正常/恢复负例弃权。规则在这 4 个正例均无语义输出。
- 24 条人工候选回放：完整审核保留 12 条有支持观察，有效覆盖 8/15；仅引用审核仍放行 3 条不受支持声明。不能把这个数字说成真实模型误报改善。
- 真实小样本中新审核和直接 LLM 都正确，未证明审核额外提升。合计 7537 Token，平均模型请求约 2.062 秒，账单未核验。
- 新 15、旧 Python 36、旧归因 TS 71 项通过。未重跑全平台历史 945 项，也没有修复历史全库类型问题。
- 同作者合成标签、冻结流程失败和真实数据不足使严格推广验收不通过，因此保留 Shadow。能解释不推广的依据，也是工程判断的一部分。

不能说：“生产根因准确率 100%”“已定位所有内部责任模块”“独立未见测试全面通过”“真实审核误报降低到零”。

## 按从零实现的顺序学习

1. 先读 `IMPLEMENTATION_AUDIT.md`，画出评测与独立诊断两条链，理解诊断不能污染评分。
2. 读原 `baseline/adapter.py` 的 validate/analyze，理解跨语言输入边界、显式异常与 unknown。
3. 读 `data/build.py` 的 A/B/C，手动沿 user→call→tool→assistant 判断哪个字段能证明观察。
4. 读 `shadow/candidate.schema.json`，先写一个合法候选，再分别改错 quote、scope、比较值、claimLevel，观察审核差别。
5. 读 `shadow/semantic_review.py` 的 review、paired、has、data；重点看同字段上下文、最新结果、实体匹配与规范摘要。
6. 读 `shadow/client.py` 的 prepare/generate；理解输入预算、非可信 Trace、密钥生命周期、超时和失败隔离。
7. 读 `run_experiment.py` 的 stats 和 `summarize.py`；从 `per-case.csv` 找到一条事实正确但证据无效的案例，解释为何不能接受。
8. 最后读 `PROMOTION_DECISION.md`：学习质量门禁如何决定保持实验版，而不是以代码量或通过率决定上线。

## 仍需解决的技术问题

自然语言中的否定、时间和单位；嵌套字段抽取的可验证性；多实体/跨工具可信结果选择；缺失和并行调用的顺序证明；真正根因的干预/恢复证据；经审查的生产数据与独立标注。上述均是待研究方向，本轮没有实现为可用能力。

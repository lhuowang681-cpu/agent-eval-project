# 最小语义归因与可信审核设计

本轮解决的是“工具没有报错，但 Agent 的输入或回答与任务/结果矛盾”。新增的是有限、可核验的跨步骤观察，不承诺自动找到内部根因。实现仅在 Shadow 运行。

## 方案比较与决策

| 方案 | 优点 | 缺点 / 决策 |
| --- | --- | --- |
| 继续扩展旧 14 类异常关键词 | 便宜、兼容 | 无法表达跨步骤语义关系；不选 |
| 自由文本 LLM 根因分类 | 灵活 | 原文引用不能证明因果；不选 |
| LLM 产生结构化关系，再审核局部原始字段 | 保留跨步发现能力，可分离引用与支持 | 可证明范围较窄；本轮选择 |
| 再用一个 LLM 判断前一个 LLM | 能覆盖自然语言 | 增加成本，裁判仍可能幻觉；本轮不做 |
| 直接改平台默认审核 | 自动覆盖现有流量 | 未满足独立质量验收，有回归风险；不做 |

## 模块和版本化合同

`shadow/candidate.schema.json` 描述独立 v1 合同；`semantic_review.py` 的运行时校验为权威，另有节点唯一性、顺序、scope、同值类型等语义检查。旧诊断 Schema 不变。

顶层：schemaVersion、原 scope、原 inputDigest、decision、observations。decision 支持 candidates / unknown / abstain / needs_review。空观察代表弃权或未知，不计为正确观察。每条带 id、三类 category、claimLevel、summary、原始 evidenceRefs、comparison={key,expected,actual}。不接收 confidence/moduleId；id、字段和 quote 必须对应原 Trace。

claimLevel 明确区分 observation / impact_hypothesis / root_cause。本版只将 observation 标为 Supported；其它声明保留候选并记 insufficient。不得因为根因“听起来合理”自动降级成已支持根因。审核成功时生成有边界的事实摘要，模型原 summary 始终仅保存在原候选里，未被视为逐字验证。

默认最多 8 条观察、每条 12 引用、引文 2000 字符；模型提示更保守，最多 3 条。多故障逐条审核，不要求唯一类别。字段 key 是单层标量字段，不支持任意表达式/路径执行。

## 三层审核

1. **身份与引用**：整批 scope/inputDigest 精确一致；节点 ID/sequence 唯一；若节点自带 scope 必须一致。每条原节点、字段、非空摘录真实存在。inputDigest 在此是输入绑定标识，不是独立签名；合成 fixture 中也不是内容 SHA。调用方必须提供可信输入快照。
2. **局部命题**：只用已引用 content/arguments 中的结构化字段值证明关系；可以使用同一被引字段中的必要 JSON 封装与实体上下文，不把摘录变成孤立节点。不得借未引用 error 或其它字段证明业务值。调用身份/顺序等 envelope 元数据仅用于配对和冲突检查。
3. **因果边界**：不从比较结果推出具体内部模块、唯一任务失败原因或因果影响。完整性不足原样保留；局部支持不等于全局 Trace 完整。需要因果链的声明持续 Needs Review。

全局 coverage.complete 不再一票否决这个**新合同的有限局部观察**。仍要求所有局部必要字段、同实体与有效调用关系。没有去掉旧默认审核的门禁。

## 每类命题的证明条件

| 类别 | 必须引用和验证 | 不足时处理 |
| --- | --- | --- |
| A parameter_task_mismatch | 调用前最近 user.content 的明确 JSON 要求 + 该 call.arguments；同 key 严格类型比较且不相等，已知工具来源 | 自然语言要求、隐含单位/年份推理未实现，needs_review |
| B answer_tool_mismatch | 最后 assistant.content + 答案前同 orderId 的最新成功工具 content；success=true、data 对象、无 error、唯一更早调用可配对、来源已知 | 不明来源、跨实体、未配对、跨工具源冲突拒绝支持 |
| C stale_information_use | B 所有条件 + 被引用的同工具/同实体旧结果；最终值与旧值相等、与新值不同 | 只能证明旧值使用模式，不能证明 Agent 的真实内部注意力或心理过程 |

“最新”只在可见顺序内有效；缺失了后续相关结果仍会影响可信度。成功封装和 mcp/plugin/builtin 来源不能证明工具反映客观事实，当前合成实验预设这些结果可信。跨工具权威性、外部数据时效和并行序关系尚未解决。

自然语言、嵌套动态 Schema、多实体聚合和否定/单位换算并不自动接受。候选可存在，但维持 Needs Review。当前实现可视为 LLM 发现 + 受限结构比较器，不能宣传成通用自然语言语义证明器。

## 模型与隐私边界

`client.generate` 支持 model 参数，默认 deepseek-flash，关闭 thinking、JSON 输出、单次最多 800 输出 Token、35 秒 socket 超时、不重试、响应不超过 256KB。输入不超过 10000 字符/30 节点，超限整体拒绝，不静默截断。运行实验最多 6 次，用 ledger 阻止自动重复。

35 秒是 urllib 网络操作超时，不是强保证的整进程绝对截止；恶意慢速分块、供应商已接收后的计费取消没有严格验证。本轮未构建后台常驻任务，不影响原评测状态。

Trace 一律作为不可信数据，系统提示明确禁止执行其中指令。结构化审核降低可接受声明范围，但不声称完全解决 prompt injection。真实模型未测试攻击轨迹，注入样例只在人工回放中覆盖。

当前外发只允许 origin=synthetic；阻止常见 key/Bearer/email 文本，默认不外发真实用户数据。origin 由调用方声明，正则不是完整脱敏器；生产外发审批、全面 PII 清洗尚未实现。官方 HTTPS 端点或严格解析的 127.0.0.1 Mock 端点才允许，禁止重定向、URL 用户信息、外部代理和非白名单主机。密钥仅从进程环境或隐藏交互读取，不落盘，不记录响应错误正文。

## 技术决策记录

- ADR-01：三类语义观察独立版本，不塞进旧异常 14 类；保留兼容性。
- ADR-02：原始候选与可支持命题分开保存，避免审核改写被误计为原根因正确。
- ADR-03：同字段上下文可用，未引字段不借用；修复第三轮短摘录设计缺陷的方向，但不改历史候选。
- ADR-04：Shadow 独立标准库进程；不新增微服务、不接 DB、不改评分任务。
- ADR-05：只支持明确结构事实；无法证明的自然语言和因果持续弃权。
- ADR-06：真实 API 预算 6 次，不重试；原始响应与费用未知状态均保留。
- ADR-07：证据不够独立，保留原型，不提出上线合并。

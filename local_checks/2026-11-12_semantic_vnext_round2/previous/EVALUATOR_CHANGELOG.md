# 评估器修订与过程限制

这些修订改变的是统计脚本和输入边界，不修改数据 JSONL、Gold、真实模型输出或历史阶段记录。最终指标来自 `summarize.py`；旧指标保留在 `*.initial-metrics.json` 和原摘要文本，不能混用。

## 指标错误与修复

1. 初版真实输出评估过度沿用固定候选标签，未逐项核对模型实际 comparison；这会把其它比较值也算正确。改为按作者预设机制核对 category + comparison + observation，另查实际原文引用及所需节点。新增指标回归。
2. 曾把根因级声明的底层字段关系命中计为正确，或直接算普通错误。根因/影响在本合同下不可判，现单列 unknownClaims；verifiedRootClaims=0，rootAccuracy=null。
3. missing 数据只有缺失后的 Trace，初始布尔标签不能区分“已知错误”与“无从确认”。最终统计记不可判，原标签保留并披露歧义，既不当正确也不算经证实的错误。它不进入可观察语义正例分母。
4. False Gap 初版未区分事实碰巧正确与证据支持。现比较原始候选中独立核对为足够支持的有限命题，与最终保留命题。没有支持的假引用/跨 scope 拒绝不算误拒；全部漏检仍通过覆盖率显示。
5. 有效覆盖必须要求事实和证据同时有效；不能用“某个类别出现在列表里”代替命中。

最终真实模型组仍为 6 个正确且支持的有限观察；固定回放最终为 dev 8/1/2、holdout 16/2/3（正确/错误/不可判）。事实正确且引用无效的候选仍可计事实正确，但不计有效覆盖。

## 测试后代码补强

测试/保存真实输出之后补充了未知决策和畸形候选保护、重复/无效节点顺序、显式节点 scope 检查、严格本机 URL 解析（阻止 userinfo 伪装 loopback）、离线 CLI 和指标回归。源码最终状态不是所谓未见测试前的完整冻结状态。

这些补强没有调整类别判断阈值或修改 fixture/gold；`summarize.py` 对所有已存候选重新调用最终审核器，断言与保存审核结果逐字对象相等，然后只重算指标。原真实输出 records SHA 保存在 summary。不能因此宣称它们是新的未见泛化实验。

没有保留第一次冻结之前的完整算法源码快照，只有后续的 `ALGORITHM_FREEZE.json`；因此不声称能逐字重放每一个早期开发中间态。原阶段历史源码/负结果完整保留，本轮最终代码和旧默认快照可以复现。

## 环境和回归

最初本机 HTTP Mock 受沙箱限制失败，日志为 tests-initial/tests-direct；允许本机网络后通过，tests-network 和最终 shadow.log 保留。没有改断言绕过网络测试。

原 Python 36 项、原 TS 71 项只按本轮实际最终一次计数，不把重复运行累加。新增 15 项包含批量子场景，不能按子场景再虚增测试数。历史 945 项、真实 PG/UI 和类型检查本轮未重跑。

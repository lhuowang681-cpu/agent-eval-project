# 推广决策：保留独立 Shadow，暂不接入默认链路

新增 LLM 在六次真实调用的合成任务上弥补了规则的三类语义盲区：4 个正例检出 6 个有支持观察，2 个负例弃权。新增审核在人工错误候选回放中阻止了虚假引用、跨 scope、错误比较和无依据根因。结果有价值，但不足以批准生产推广。

| 验收要求 | 本轮证据 | 决定 |
| --- | --- | --- |
| 原合同、默认诊断、评分不变 | 关键 10 文件 SHA 未变，原 36 Python + 71 TS 通过 | 通过限定回归范围 |
| 新语义链可运行 | 新 15 测试、本机 HTTP Mock、6 次真实 DeepSeek | 通过原型可运行性 |
| 相比规则有效覆盖提升 | 真实模型/合成 0/4→4/4；人工回放 0/15→8/15 | 有限证据，不能外推 |
| 不接受无证据根因 | 回放 root 拒绝，模型无此声明；因果准确率 NA | 通过当前边界测试 |
| 严格独立未见验收 | 同一作者、重复模板；测试前哈希冻结失败，测试后有健壮性补强 | **不满足** |
| 真实自然场景有效性 | 无可靠脱敏生产 gold；仅结构化小样本 | **未验证** |
| 错误风险与成本足够可靠 | 真实 6 请求，无失败压力样本；usage 有、账单无 | **证据不足** |

没有 feature flag 需要开启，因为本轮没有平台集成入口。默认规则和原 Evidence Review 仍按原路径执行；新目录既不接诊断数据库也不回写评分。旧审核的已知保守限制没有被宣称修复。

## 关闭与回滚

停止运行本目录实验脚本即可关闭，原平台不受影响。若不保留候选，可以移出本目录；不需要应用反向数据库迁移或替换平台文件。`baseline/` 是便携快照，不要将其覆盖到平台。已有 `real_attempts.json` 阻止自动第二轮付费调用，不删除预算账本来重跑。

`SOURCE_FREEZE.json`/`results/default_unchanged.json` 保存关键默认文件对比；原第三轮负结果、补丁和回滚记录没有改动。`ALGORITHM_FREEZE.json` 保留失败冻结过程的限制；最终文件哈希另放 `FINAL_MANIFEST.json`，不回填成测试前记录。

## 继续推进前需要的最小证据

1. 在方案与哈希真正冻结后，由不同标注者准备未披露测试集；人工复核事实、引用、支持与根因四个标签，记录分歧。不复用当前 36 条冒充新测试。
2. 经脱敏审查后导出少量真实任务，检查调用配对、并行顺序、数据时效和工具可信度。生产 Trace 默认仍不允许外发。
3. 在明确的新预算下测试困难样本、错误引用、注入、缺失和自然语言；扩展字段提取时保持“提取文本→原字段引用→审核”可追溯。不能用模型自报置信度证明提取正确。
4. 单独评估审核误拒与 False Support。若自然语言支持无法独立验证，维持候选或人工复核，不以覆盖率为理由放行。
5. 以上质量验收通过后，才比较复用平台 ModelRuntime + 原独立任务 worker 的默认关闭集成方案；保留规则、评分不变、独立结果存储。这里是后续设想，**尚未实现或承诺上线**。

本轮结论是继续研究价值成立、正式推广条件未通过。没有把合成小样本的零观察错误包装成生产零风险。

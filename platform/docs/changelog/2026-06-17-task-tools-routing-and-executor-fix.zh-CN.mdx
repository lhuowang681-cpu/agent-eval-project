# 任务工具路由优化与执行器修复 🛠️

本次更新修复了 `lobe-task` 工具调用长期处于 loading 状态的遗留问题，优化了 `lobe-task` 与 `lobe-gtd` 之间的工具路由（让「定时 / 周期」类请求能稳定命中正确工具），并清理了过时的 Task Skill 引用。

## 🐛 问题修复

- 🔧 **修复 `lobe-task` 工具调用一直 loading**：此前任何 `lobe-task/*` 调用（如 `createTask`、`listTasks`、`setTaskSchedule`）都会永远停在「加载中」，且不报错。原因是执行器已经实现，但从未在前端执行器注册表中注册。本次补齐了包上的 `./executor` 子路径导出，并把 `taskExecutor` 注册到 builtin executor 列表中。

## 🌟 体验优化

- 🧭 **`lobe-task` 与 `lobe-gtd` 路由更清晰**：
  - `lobe-task` 的工具简介新增 **「自动化调度（cron /heartbeat/ 周期性执行）」** 关键词，让「每天早上 10 点…」这类请求在工具筛选阶段就能命中。
  - `lobe-gtd` 的工具简介明确其后台任务为 **「一次性（one-shot）」**，并引导周期性需求改用 `lobe-task`。
  - 两边 system prompt 都加了简短的路由段（`<when_to_use>` / `<vs_task_tools>`），明确边界并覆盖中英文触发词（定时 / 每天 / 每周 /cron/schedule/periodically/heartbeat）。
- 🧹 **清理过时的 Task Skill 引用**：`packages/builtin-skills` 下的 `task` skill 描述了一套在 `@ctrip/tripyoyo-cli` 中并未实现的 `lh task` CLI。本次从 builtin-skills 索引与 taskRunner 插件列表中移除其注册。skill 源文件保留在磁盘上，但不再被加载。

## 💡 选择指南

| 用户意图                        | 工具                             |
| --------------------------- | ------------------------------ |
| 定时任务 / 每天 / 每周 /cron/ 周期性执行 | `lobe-task`（`setTaskSchedule`） |
| 快速待办清单 / 计划文档 / 一次性后台研究     | `lobe-gtd`                     |
| 带子任务、依赖、指派 agent 的结构化任务     | `lobe-task`                    |

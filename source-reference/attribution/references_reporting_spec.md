# Langfuse Trace Badcase 报告规范

## 1. 正式硬错误

正式统计只包含：Trace 最终失败；异常直接造成任务中断或结果不可用；Trace 上下文能确认直接因果。

错误识别必须联合分析 final status、is_error、error type/detail、Message Content、Tool Input/Output/Observation、重试恢复、父子关系和最终任务完成状态。

## 2. 软错误改进指标

工具错误后改用其他工具、前置异常后恢复、重试成功、未终止 Trace 的节点失败、最终任务成功的异常，均放入独立“软错误改进指标”，不计入正式 Badcase 数量与硬错误分布。

软错误需要独立统计：受影响 Trace 数、软错误事件数、固定错误类别、能力层与模块、失败工具及输入、失败输出、替代/恢复路径、失败后额外节点数。软硬错误不得合并计算数量或百分比。

## 3. 节点角色

- root_cause：最早直接导致任务失败的节点；
- error_exposure：明确暴露/记录错误的节点；
- propagation：受上游错误影响但自身非根因。

根因节点分为：确认根因节点（Trace 直接记录异常输入/输出）、推断根因节点（内部节点未单独埋点，但可由下游字段级 Error Detail、输入输出和直接因果链反推）、无法定位。只有证据不足以建立直接因果链时才填“待确认”。推断根因必须展示反推输入、输出、依据，并标明非独立 Span。

## 4. 去噪与完整证据

主视图保留用户原始请求、关键输入、根因节点、必要 Tool Input/Output/Observation、错误暴露、必要传播路径和最终失败结果。默认折叠 Node ID、Parent ID、重复系统提示、无关推理、无关成功节点、已恢复重试和低价值元数据。Topic ID 必须保留。

人类可读的 Trace 证据链不得用 `...`、`…`、`nan` 等占位符替代关键输出。若源数据本身只有占位符，必须明确写“源数据无有效模型输出”，并优先展示 Error Detail。默认不生成 LOSSLESS_MANIFEST 或分片工作表；完整技术字段保留在 TECH_AUDIT，需要额外无损导出时再单独生成。

## 5. 固定 Case 格式

1. Case 标识：错误类别、序号、Topic ID、时间
2. 一句话结论
3. 用户任务
4. 最终影响
5. 根因定位：根因节点、报错节点、能力层、模块、函数/接口、置信度
6. 错误证据
7. 精简调用链：用户请求 → 模型决策 → 工具调用 → 根因 → 传播 → 最终失败
8. 修复建议：立即修复、防御性处理、监控与测试补充
9. 软错误观察项

## 6. 固定分类字段

输出必须包含固定树中的 layer_id/module_id；一级/二级错误类别只能来自维护的固定枚举。未知分类使用 UNKNOWN，不创建近义名称。

## 7. 批量门禁

正式批量前必须输出 3 个不同类型样例，人工确认错误口径、去噪规则和归因质量后，才能批量生成报告。
